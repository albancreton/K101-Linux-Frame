# K101 Linux Frame

Mainline Linux on a cheap Android photo frame, turned into an always-on touch dashboard.

The frame is a 10.1" "K101" digital photo frame (sold as *Kelarior*, stock Android 6.0.1) built
around an **Allwinner A33**. This repository boots it from a microSD card into:

- **U-Boot v2026.10**
- **Linux 6.18 LTS**
- **Debian 13 (trixie, armhf)**
- **`cage` + WPE WebKit (`cog`)**, showing one web page full screen

The internal NAND, which holds the stock Android, is never touched. Pull the card and the frame
boots Android again.

Everything here was brought up without a serial adapter: only ADB on the rooted stock firmware
and a USB cable on the frame's OTG port. If you have the same frame (or another A33 tablet-class
board), you or your coding agent should be able to reuse most of it. Read the
[notes for agents](#notes-for-agents) first.

## What works

| | |
|---|---|
| Display | 800×1280 MIPI-DSI panel (JD9365DA-H3), used as 1280×800 landscape, 38 Hz |
| GPU | Mali-400 MP2 via `lima` (GLES2); WPE composites on it |
| Touch | Silead GSL1680, calibrated, jitter-filtered, multitouch |
| Wi-Fi | RTL8188FU via `rtl8xxxu`, managed by `iwd` |
| Remote access | SSH, Tailscale, plus a USB network link (`10.42.0.1`) on the OTG port |
| CPU | 4×Cortex-A7 up to 1.2 GHz with thermal throttling |
| Kiosk | `cage` + `cog`, restart on crash, corner long-press menu (hard refresh, reload, home) |
| Safety net | SoC watchdog armed from U-Boot, fed by systemd |

Not used, and not brought up: audio, the accelerometer (`mir3da`), camera, battery and the side buttons.

Scrolling a dashboard-like page runs at about 20 fps. Compositing happens on the GPU, but WebKit
paints page content on the CPU, so this is close to the limit of the hardware.

## How it boots

1. **BootROM:** the A33 tries the microSD card before NAND.
2. **U-Boot SPL and U-Boot** sit in the card's raw area at 8 KiB. U-Boot runs `boot.scr` from the FAT partition.
3. **`boot.scr`** ([`board/u-boot/boot.cmd`](board/u-boot/boot.cmd)):
   - If the file `dashframe-fel` exists on the FAT partition, it drops into USB FEL mode, so the frame can be reflashed over USB.
   - Otherwise it arms the 16 s watchdog and boots `zImage` and the DTB.
4. **Linux** mounts `mmcblk0p2` as root. systemd starts networking, `iwd`, Tailscale and the kiosk (`kiosk.service`: `cage -s -- dashframe-kiosk`), which opens `DASHBOARD_URL` from `/etc/dashframe.conf`.

Card layout (MBR):
- **Raw area:** U-Boot at 8 KiB.
- **p1:** FAT, with `zImage`, `sun8i-a33-k101-frame.dtb` and `boot.scr`.
- **p2:** ext4 root. It grows to fill p2 on first boot, so make p2 as large as you want the root.

## Not in this repository

Some files exist on a working frame or in a working checkout but are not committed. Here is
how to recreate each one.

| Path | What | How to get it |
|---|---|---|
| `src/u-boot`, `src/linux` | Upstream sources (pinned tags) | `build/fetch-sources.sh` |
| `out/` | Build outputs, logs | the `build/*.sh` scripts |
| `secrets/<SSID>.psk` | Wi-Fi credentials in [iwd format](https://man.archlinux.org/man/iwd.network.5), copied to `/var/lib/iwd/` | create it yourself (see below) |
| `secrets/dashframe.conf` | Your `/etc/dashframe.conf` (dashboard URL...); replaces the placeholder in the image | copy `board/rootfs/overlay/etc/dashframe.conf` and edit it |
| `secrets/dashframe_ed25519` | Passphrase-less dev SSH key used by `tools/frame-ssh` | generated by the first `build/build-rootfs.sh` |
| `secrets/frame-state.tar` | Tailscale identity, SSH host keys and browser data saved before a reflash, restored by `install-sd.sh` | command in [Reflashing](#reflashing-keeping-tailscale-and-host-keys) |
| `hw/modules/*.ko` | Vendor kernel modules from the stock firmware, used only as reverse-engineering reference | `adb pull /system/vendor/modules/<name>.ko hw/modules/` on a stock frame |
| Tailscale login | Node identity in `/var/lib/tailscale` | run `tailscale up` once on the frame and approve it |

The touch firmware, `hw/firmware/silead/gsl1680-k101-frame.fw`, *is* committed, because touch
doesn't work without it. It was converted from the `GSL1680F_ZSK_1975` table inside the vendor
`gslX680new.ko` into the mainline `silead` format.

Wi-Fi credentials, created without them ever going through a chat or the shell history:

```sh
bash -c 'read -rp "SSID: " s; read -rsp "Passphrase: " p; echo;
  printf "[Security]\nPassphrase=%s\n" "$p" > "secrets/$s.psk"; chmod 600 "secrets/$s.psk"'
```

## Building

The host needs:
- **Docker**, for the cross toolchain and `mmdebstrap` (see [`build/Dockerfile`](build/Dockerfile)).
- **`qemu-user-static`**, with binfmt registered, for the armhf rootfs.
- **`sunxi-tools`** (`sunxi-fel`).

```sh
build/fetch-sources.sh      # U-Boot v2026.10, Linux v6.18.59 into src/
build/build-uboot.sh        # out/u-boot/u-boot-sunxi-with-spl.bin
build/build-linux.sh        # out/linux/.../zImage, sun8i-a33-k101-frame.dtb, modules
build/build-initramfs.sh    # out/initramfs.cpio.gz (busybox; used only for installing)
build/build-rootfs.sh       # out/rootfs.img (3 GB ext4, Debian 13 + kiosk)
```

The board-specific parts are all under [`board/`](board):

- **`board/dts/sun8i-a33-k101-frame.dts`:** device tree, shared by U-Boot and Linux.
- **`board/u-boot/`:** defconfig (DRAM parameters, USB gadget, watchdog) and boot scripts.
- **`board/linux/k101.config`:** config fragment on top of `sunxi_defconfig`.
- **`board/linux/patches/`:** two kernel patches:
  - the panel's init sequence and timings, added to `panel-jadard-jd9365da-h3`;
  - a retry for the flaky Silead probe.
- **`board/rootfs/`:** package list (in `build-rootfs.sh`), `customize.sh`, and a file overlay with the kiosk, menu, udev rules and systemd units.

For U-Boot and FEL, allow access to the Allwinner USB IDs, and keep ModemManager away from the
frame's USB serial console:

```
# /etc/udev/rules.d/99-allwinner.rules
SUBSYSTEM=="usb", ATTRS{idVendor}=="1f3a", MODE="0666"
SUBSYSTEM=="tty", ATTRS{idVendor}=="1f3a", ENV{ID_MM_DEVICE_IGNORE}="1"
```

## First install

What we did, using the rooted stock Android (ADB over Wi-Fi), a microSD card in the frame and a
USB cable from the frame's OTG port to the PC:

1. **Prepare a card** with an MBR, p1 FAT32 (256 MB is plenty) and p2 Linux. We reused a Raspberry Pi OS card's partitions.
2. **Write U-Boot and the FEL marker from Android.** On the stock firmware the SD card is `/dev/block/mmcblk0`, because the internal storage is raw NAND.
   ```sh
   adb push out/u-boot/u-boot-sunxi-with-spl.bin /data/local/tmp/
   adb shell 'dd if=/data/local/tmp/u-boot-sunxi-with-spl.bin of=/dev/block/mmcblk0 bs=1024 seek=8'
   ```
   Then copy `boot.scr` and an empty `dashframe-fel` file onto the card's FAT partition. Build `boot.scr` with
   `out/u-boot/tools/mkimage -A arm -T script -C none -d board/u-boot/boot.cmd out/boot.scr`.
3. **Reboot into FEL.** The frame boots from the card, blinks the backlight twice and enters FEL. The PC sees `1f3a:efe8`.
4. **Boot the installer over USB:** `tools/fel-boot-linux.sh` loads U-Boot, the kernel and the initramfs. The frame shows up as a USB network device at `10.42.0.1`.
5. **Install:** `tools/install-sd.sh` streams U-Boot, the boot files, the rootfs, your `secrets/*.psk` and the saved state to the card, then removes the FEL marker.
6. **Reboot the frame:** `tools/frame-sh.py 'reboot -f'`. It comes up on your dashboard.
7. **Join your tailnet:** `tools/frame-ssh tailscale up`, then approve the node.

Without Android, the standard sunxi card layout should work the same way from a PC card reader, though this path wasn't tested on this frame:
- U-Boot `dd`'d at 8 KiB;
- the boot files on p1;
- `out/rootfs.img` `dd`'d to p2, then `resize2fs`.

Touch calibration was done once with
[`calibrate.html`](board/rootfs/overlay/usr/local/share/dashframe/calibrate.html) (tap 5 targets).
The resulting matrix is in
[`99-dashframe-touch.rules`](board/rootfs/overlay/etc/udev/rules.d/99-dashframe-touch.rules).
Another unit may need its own calibration.

## Day to day

- **Change the page:**
  ```sh
  ssh root@dashframe "sed -i 's|^DASHBOARD_URL=.*|DASHBOARD_URL=https://new.example|' /etc/dashframe.conf && systemctl restart kiosk"
  ```
- **Menu:** hold a finger in the top-left corner for 2 s. The backlight blinks, then the menu opens:
  - **Hard refresh:** clears WebKit's HTTP cache and restarts the browser.
  - **Reload page.**
  - **Dashboard.**
  - **Close.**

  `MENU_CORNER` and `MENU_HOLD_SECONDS` in `/etc/dashframe.conf` change the corner and hold time.
- **Shell:**
  - `tools/frame-ssh [cmd]`, over the USB link by default, or `FRAME=dashframe tools/frame-ssh` over Tailscale.
  - `tools/frame-sh.py` gives a shell on the USB serial console, even without networking.
- **New kernel or DTB:** run `build/build-linux.sh && tools/update-kernel.sh`. This pushes the kernel, DTB and modules over SSH, then reboots.
- **Fallback browser:** `BROWSER=chromium` in `/etc/dashframe.conf`. It's much slower; see below.
- **Back to Android:** power off, remove the card.

### Reflashing (keeping Tailscale and host keys)

```sh
tools/frame-ssh 'tar -C / -cpf - var/lib/tailscale etc/ssh/ssh_host_* home/kiosk/.local/share/wpe' > secrets/frame-state.tar
tools/frame-ssh 'touch /boot/firmware/dashframe-fel; reboot'   # next boot enters FEL
tools/fel-boot-linux.sh
tools/install-sd.sh
tools/frame-sh.py 'reboot -f'
```

## What we found

The non-obvious parts, roughly in the order they bit. Details and sources are in
[`hw/HARDWARE.md`](hw/HARDWARE.md).

**Board**
- **CPU rail:** the CPU runs on **DCDC3**, not DCDC2 as in Allwinner's reference tablet design. The kernel hung as soon as cpufreq touched the wrong rail. The stock firmware runs the CPU at 1.32 V at 1.2 GHz.
- **DRAM:** 16-bit DDR3 at 552 MHz. The parameters come from the stock `sys_config`.
- **Wi-Fi power:** the RTL8188FU sits on the internal USB1 host port and is powered through PL6.

**Display**
- **Wrong panel name:** the panel is a **JD9365DA-H3**, even though `sys_config` names an ILI9881C. The vendor `lcd.ko` contains several init tables, and each one sits *before* the panel struct that uses it. Picking the wrong one gives a grey, washed-out, fading image.
- **Video mode:** DSI must be **non-burst**. In burst mode the panel accepts the init sequence but never refreshes.
- **Porches:** the stock 2-pixel HBP is below the minimum blanking packet that sun6i DSI can send, so lines run long and the panel periodically loses sync. We moved 18 pixels from HFP to HBP.
- **Pixel clock:** at the stock **53 MHz**, the panel drops individual lines (they keep the previous frame) whenever the CPU is busy. This happens even with pure CPU load and no memory traffic. These did **not** help:
  - DRAM master priorities;
  - a faster MBUS;
  - a fixed CPU clock;
  - forcing the DC-DCs into PWM mode.

  **45 MHz (~38 Hz)** is clean. [`tools/display-load-test.sh`](tools/display-load-test.sh) reproduces it.
- **Rotation:** the panel is mounted rotated: DT `rotation = <270>`, `fbcon=rotate:1`, and `wlr-randr --transform 270` in the kiosk.

**Touch**
- **Axes:** only X is inverted. The raw range covers just part of the screen (~x 255..1286, y 10..640), so a libinput calibration matrix maps it.
- **Flaky probe:** the controller sometimes fails its first chip-ID read after power-up. Patch 0002 retries.
- **Jitter:** a resting finger moves 1–3 raw units per frame, which makes WebKit scroll up and down. A hwdb `EVDEV_ABS_*` fuzz fixes it. libinput's own udev rule moves that fuzz into userspace hysteresis, which it applies to touchscreens too.

**GPU and browser**
- **No GLES3:** the Mali-400 only does GLES2. Chromium needs GLES3, so it falls back to SwiftShader (CPU rendering, **2 fps** scrolling). WPE WebKit composites on `lima` (**~20 fps**) and also uses less RAM.
- **Sandbox:** logind gives local sessions an ambient `CAP_WAKE_ALARM`, and bubblewrap (WebKit's sandbox) refuses to start with it. `kiosk.service` drops it from the bounding set.
- **Slow stop:** `cog` ignores SIGTERM, so `TimeoutStopSec=3`.

**CPU and power**
- **Thermal sensor:** on the A33 it's driven by `sun4i-gpadc-iio` (`CONFIG_SUN4I_GPADC`), not `sun8i-thermal`. Without it nothing throttles.
- **Heat:** under full load it throttles at ~86–89 °C, settling at 1.0–1.1 GHz.
- **Governor:** schedutil's default rate limit (366 µs) is far shorter than a real frequency switch, which goes through the PMIC over RSB. The governor thread ate ~30% of a core, so the image sets 50 ms.

**Kernel config needed by userspace**
- **`iwd`:** a list of crypto user-API options, plus `RFKILL`.
- **zram:** `ZRAM_BACKEND_ZSTD`.
- **Tailscale:** TUN and nftables.
- **systemd:** the usual cgroup, BPF and namespace options.

All of these are in `k101.config`.

## Notes for agents

- **No serial console:** the bring-up loop is USB only.
  - The SD card's `boot.scr` drops into FEL when `dashframe-fel` exists, and `tools/fel-uboot.sh` loads U-Boot over USB.
  - `tools/ubcmd.py` drives the U-Boot prompt over USB ACM (`/dev/ttyACM0`); `reset` returns to FEL.
  - `tools/fel-boot-linux.sh` boots a kernel and captures its console to `out/console.log`.
- **Recovering from hangs:** U-Boot arms the 16 s SoC watchdog before every kernel boot, so a hang resets the frame. DRAM doesn't survive that reset, so capture the console live rather than hoping to read logs back afterwards.
- **Screenshots lie for display bugs:** `grim` captures what the compositor rendered, not what the panel shows. For flicker, tearing or lost lines, ask the human to look, and use a deterministic test pattern like `linetest.html`.
- **`pkill -f` gotcha:** don't `pkill -f` a pattern that also appears in your own command line. It kills your own shell or SSH session. Use `pgrep -x` / `pkill -x`.
- **Pipe buffering:** `libinput debug-events` and `mawk` both buffer when piped. Use `stdbuf -oL` and `mawk -W interactive` for anything event-driven.
- **Secrets:** Wi-Fi credentials go in `secrets/*.psk` files that the human creates. Never ask for them in chat.
- **Don't write the NAND.** It's the only way back to the stock firmware.
